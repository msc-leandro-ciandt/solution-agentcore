# Root Cause Analysis: Session 404 Bug

## The Problem

Users were getting 404 errors when trying to view sessions:
```
GET /sessions/cf66e1bc-a571-47bd-81b7-f026bdd3d382 → 404 Not Found
```

But the sidebar showed sessions listed. Why?

---

## Root Cause: Sessions Never Created in DynamoDB

The backend returns 404 when a session doesn't exist in DynamoDB. Sessions are created lazily - only when `PUT /sessions/{sessionId}` is called (the "touch" endpoint).

### The Flow That SHOULD Happen:

1. **User sends first message**
   - Frontend generates random `sessionId` via `crypto.randomUUID()`
   - Sends to AgentCore Runtime
   - Agent responds, saves exchange to AgentCore Memory
   - ✅ Memory now has conversation

2. **Frontend calls "touch" to create metadata**
   - `touchSession(sessionId, firstUserMessage, firstAssistantMessage, idToken)`
   - Calls `PUT /sessions/{sessionId}`
   - Backend creates DynamoDB row with title (generated by Claude Haiku)
   - ✅ DynamoDB now has metadata row

3. **Session appears in sidebar**
   - Frontend lists sessions via `GET /sessions` (queries all user's sessions from DynamoDB)
   - ✅ Session is visible

4. **User clicks session**
   - Frontend calls `GET /sessions/{sessionId}`
   - Backend finds row in DynamoDB ✅
   - Fetches messages from Memory ✅
   - Returns 200 with metadata + messages

### What Was Actually Happening:

Step 2 was **FAILING silently**. The `touchSession()` call was using `auth.user?.id_token` from `react-oidc-context`, which:
- Was undefined/null
- Was incorrectly formatted
- Was not being passed correctly

Result: `PUT /sessions/{sessionId}` would fail, DynamoDB row never created, so later `GET` calls returned 404.

---

## The Fix

### Root Cause in Code:

**File:** `frontend/src/components/chat/ChatInterface.tsx` (line ~180)

```typescript
// ❌ BROKEN - relies on react-oidc-context auth state
const idTokenForTouch = auth.user?.id_token
if (idTokenForTouch) {
  touchSession(sessionId, firstUserMessage, firstAssistantMessage, idTokenForTouch)
}
```

**Problem:** `auth.user?.id_token` is not reliably populated in react-oidc-context.

### Solution:

Pass `idToken` as a prop from `ChatPage` where it's properly managed:

**File:** `frontend/src/routes/ChatPage.tsx`

```typescript
// ✅ CORRECT - idToken properly managed in ChatPage
<ChatInterface
  key={sessionId}
  sessionId={sessionId}
  initialMessages={initialMessages}
  idToken={idToken}  // ← Pass the proper idToken
  onRequestNewChat={handleNewChat}
  onSessionTouched={refreshSessions}
/>
```

**File:** `frontend/src/components/chat/ChatInterface.tsx`

```typescript
// ✅ CORRECT - receive as prop and use
interface ChatInterfaceProps {
  idToken?: string  // ← Add prop
  // ... other props
}

export default function ChatInterface({
  idToken,  // ← Receive prop
  // ... other params
}) {
  // ... later in sendMessage() callback:
  
  if (idToken) {
    touchSession(sessionId, firstUserMessage, firstAssistantMessage, idToken)
      .then(() => onSessionTouched?.())
      .catch(err => console.error("Failed to touch session:", err))
  }
}
```

---

## Why This Fix Works

1. ✅ `ChatPage` gets `idToken` from `useAuth()` hook (which works properly)
2. ✅ `ChatPage` passes it down to `ChatInterface` as a prop
3. ✅ `ChatInterface` has reliable access to the token
4. ✅ When user sends first message, `touchSession()` succeeds
5. ✅ DynamoDB row is created
6. ✅ Session appears in sidebar
7. ✅ Clicking session calls `GET /sessions/{id}` → finds row → returns 200 ✅
